## 2. เตรียมก่อนนำเสนอ

1. รัน `run.bat` เปิดที่อยู่ที่โปรแกรมแจ้ง และตรวจชื่อกลุ่ม/สมาชิก
2. หากจะสาธิตเพิ่ม ลบ หรือปิดงาน ให้ใช้ข้อมูลชั่วคราว: `.venv\Scripts\python.exe docs/qa/serve_fixture.py` เปิด `http://127.0.0.1:5002/page1` ซึ่งไม่แตะข้อมูลงานจริง
3. หากใช้ `check.bat` สำรอง data.json แยกไฟล์ก่อนและคืนหลังตรวจ เพราะตัวตรวจ reset จาก sample
4. เตรียมภาพและ [ผังงาน](FLOWCHARTS.md) เผื่อเครื่องนำเสนอมีปัญหา
5. ทดลองการแจ้งเตือนบนเครื่องที่จะใช้จริงก่อนเริ่ม ไม่รับปากว่าจะเตือนซ้ำทุกครั้งที่กด เพราะมีการจำชุดงานที่เตือนแล้ว
6. ชี้ตัวเลขจากหน้าจอที่กำลังแสดง วันคงเหลือเปลี่ยนตามวันที่เครื่อง ไม่ท่องค่าจำนวนวันจากเอกสาร

ข้อความในวงเล็บเหลี่ยมเป็นคำสั่งสาธิต ไม่ต้องอ่านออกเสียง

## 3. คนที่ 1 — นายวายุ ทาโสม

[เปิดหน้าแรก แล้วเปิด Team สั้น ๆ]

“สวัสดีครับอาจารย์และเพื่อน ๆ พวกเรากลุ่ม CodeMind กลุ่ม 6 ขอนำเสนอโครงงาน ‘เดดไลน์ไม่ชนกัน’ ผมนายวายุ ทาโสม รับผิดชอบการวางภาพรวมและ models.py ครับ

ปัญหาคือเมื่องานหลายวิชามาส่งใกล้กัน เรารู้วันส่งแต่ยังไม่รู้ว่าควรเริ่มชิ้นใด และเวลาที่มีเพียงพอหรือไม่ ระบบนี้จึงช่วยจัดงานประจำวัน ตรวจความเสี่ยง และติดตามความคืบหน้า

เราใช้ Python และ Flask ตามโครงงานอาจารย์ เก็บงานใน JSON และแสดงผลด้วย HTML/Jinja กับ CSS เดิม คงไฟล์ที่ห้ามแก้ไว้ และไม่ติดตั้ง package เพิ่ม สูตรร่วมอยู่ใน models.py เพื่อให้หน้า Overview และ Plan ใช้กติกาเดียวกันครับ

[เปิดคลาส Assignment]

ข้อมูลหลักมีเจ็ดส่วน: ชื่องาน วิชา วันส่ง เวลาทั้งหมด เวลาที่ทำแล้ว ความสำคัญ และรายละเอียดเพิ่มเติม ซึ่งรวมเจ้าของงาน งานย่อย และประวัติ

คลาส Assignment เปรียบเหมือนแบบฟอร์มมาตรฐานของงานหนึ่งชิ้น คำนวณเวลาคงเหลือ วันก่อนส่ง และเปอร์เซ็นต์ เช่น งาน 8 ชั่วโมง ทำแล้ว 2 ชั่วโมง จะเหลือ 6 ชั่วโมง และมีความคืบหน้า 25 เปอร์เซ็นต์ครับ

ถัดไปคุณลักขณาจะอธิบายว่าข้อมูลเหล่านี้ช่วยให้รู้ว่าควรทำงานใดวันนี้อย่างไรครับ”

## 4. คนที่ 2 — นางสาวลักขณา ศรีโพธิ์

[เปิด Overview ชี้ส่วนงานที่ควรเริ่มวันนี้]

“สวัสดีค่ะ ดิฉันนางสาวลักขณา ศรีโพธิ์ รับผิดชอบหน้า Overview และการเตรียมข้อมูลฝั่ง Python ค่ะ

หน้าแรกของงานมีส่วน ‘งานที่ควรเริ่มวันนี้’ แสดงชื่องาน เหตุผล และชั่วโมงที่แบ่งให้ เรียงงานเกินกำหนดก่อน จากนั้นวันส่ง ชั่วโมงที่ยังต้องใช้ ความเสี่ยง และความสำคัญ ตามเกณฑ์ทีละข้อ

ระบบแบ่งเวลารวมไม่เกินเวลาว่างที่ตั้งไว้ และหักชั่วโมงทำจริงที่บันทึกวันนี้แล้ว จึงไม่แนะนำเพิ่มเต็มวันทั้งที่เราใช้เวลาไปบางส่วนค่ะ

[ชี้สถานะและปุ่มเริ่ม]

สถานะมีข้อความ ไอคอน และสี ได้แก่ ยังไม่เริ่ม กำลังทำ และเสร็จแล้ว ส่วนใกล้ส่งหรือเกินกำหนดเป็นป้ายอีกชุด งานจึงเป็นทั้งกำลังทำและเกินกำหนดได้

ผู้ใช้กดเริ่มงานเพื่อเปลี่ยนสถานะ หรือกดทำเครื่องหมายเสร็จได้ทันที งานจะออกจากจำนวนงานค้างและไปหมวดเสร็จแล้ว หากกดปิดผิดเปิดกลับได้ โดยคืนยอดก่อนปิดค่ะ

[ชี้ปุ่มแจ้งเตือนและปฏิทิน]

การแจ้งเตือนครอบคลุมงานใกล้ส่ง เกินกำหนด แผนเสี่ยง งานวันนี้ และไม่มีอัปเดต ระบบตรวจข้อมูลล่าสุดทุกนาทีขณะเปิดหน้านี้ ต้องได้รับสิทธิ์จากเบราว์เซอร์ หากปิดหน้าให้ใช้ไฟล์ปฏิทินและนำเข้าแอปที่ใช้อยู่ค่ะ

ต่อไปคุณไกรวิชญ์จะสาธิตการเพิ่มงานและบันทึกความคืบหน้าค่ะ”

## 5. คนที่ 3 — นายไกรวิชญ์ บุ้งทอง

[เปิด Manage ในเว็บทดสอบ]

“ผมนายไกรวิชญ์ บุ้งทอง รับผิดชอบหน้า Manage และส่วนติดต่อผู้ใช้ครับ

เราแยกเวลาที่คาดว่าจะใช้ทั้งหมดออกจากเวลาที่ทำไปแล้ว พร้อมคำอธิบายใต้ช่อง เช่น งานทั้งหมด 4 ชั่วโมง ทำไปแล้ว 1.5 ชั่วโมง เพื่อไม่ให้สับสนระหว่างเวลาทั้งงานกับเวลาครั้งใหม่

[เพิ่ม ‘งานสาธิต’ วิชาเขียนโปรแกรม วันส่งอนาคต 4 ชั่วโมง ทำแล้ว 0 เลือกผู้รับผิดชอบ เปิดงานย่อยและกดขั้นตอน 6 ข้อ]

งานใหญ่แบ่งได้เป็นวิเคราะห์ ออกแบบ เขียนโปรแกรม ทดสอบ แก้ข้อผิดพลาด และเตรียมส่ง ทำให้เห็นว่ายังขาดขั้นตอนไหน งานย่อยไม่เพิ่มชั่วโมงเอง ผู้ใช้บันทึกเวลาที่ใช้จริงแยกครับ

[เปิดการ์ดและบันทึกเวลาครั้งนี้ 1.5 ชั่วโมง]

หลังบันทึก จะเหลือ 2.5 ชั่วโมง และประวัติแสดงวันที่ งาน และชั่วโมงจริง พร้อมยอดรวมรายวัน การแก้ยอดเดิมและการกดปิดงานแสดงเป็นคนละประเภท เพื่อไม่ทำให้ประวัติชั่วโมงจริงเพิ่มโดยไม่มีการทำงานครับ

ฟอร์มตรวจข้อมูลทั้งในเบราว์เซอร์และ Python เช่น ช่องว่าง ชั่วโมงติดลบ และทำแล้วมากกว่าเวลารวม หากวันส่งผ่านแล้วต้องยืนยันว่าเป็นงานค้าง

รูปแบบใช้ธีมแดงเลือดหมูและทองตามคณะ มีป้ายข้อความร่วมกับสี ปุ่มหลักสูงอย่างน้อย 44 พิกเซล เมนูขึ้นบรรทัดใหม่บนมือถือ และตารางประวัติเลื่อนในกรอบได้ครับ

หน้า Team ยังแสดงจำนวนงาน ความคืบหน้า และรายการที่ยังไม่มอบหมาย ต่อไปคุณธีรเดชจะอธิบายหน้า Plan และผลทดสอบครับ”

## 6. คนที่ 4 — นายธีรเดช ฤทธิ์คำรพ

[เปิด Plan ชี้ช่องตั้งเวลาว่างและแผงเปรียบเทียบ]

“ผมนายธีรเดช ฤทธิ์คำรพ รับผิดชอบหน้า Plan และการทดสอบครับ

หน้าแผนเปรียบเทียบภาระงานสะสมกับเวลาว่างจริง แล้วแสดงสามสถานะคือ ตามแผน เวลาไม่พอ และเกินกำหนด พร้อมชั่วโมงที่ต้องทำ มี และขาดต่อวัน

ตัวอย่างเหลืองาน 18 ชั่วโมง ส่งพรุ่งนี้ และว่างวันละ 4 ชั่วโมง เมื่อรวมวันนี้จะมีสองวัน ทำได้ 8 ชั่วโมง แต่ต้องทำเฉลี่ยวันละ 9 ชั่วโมง จึงขาดวันละ 5 ชั่วโมง หรือรวม 10 ชั่วโมงครับ

งานที่ส่งวันเดียวกันใช้ภาระรวมเดียวกัน และงานเกินกำหนดยังนับเป็นภาระของกำหนดถัดไป หลังบันทึกเวลาวันนี้ ระบบลดความจุวันนี้ก่อนจัดสรรงานเพิ่ม

[แสดงผลตรวจหรือรายงาน QA]

การตรวจอาจารย์ได้ 60 จาก 60 คะแนน โดยไฟล์ห้ามแก้คงเดิม ชุด pytest ผ่าน 42 กรณี รวมของอาจารย์ 4 และกรณีเพิ่มเติม 38 ส่วนตรรกะ JavaScript ผ่าน 4 กรณี เราลองเส้นทางเพิ่มงาน บันทึกเวลา ปิดงาน เริ่มงาน และตรวจมือถือที่กว้าง 320 พิกเซลด้วยครับ

ผลนี้ยังไม่ครอบคลุมทุกอุปกรณ์หรือระบบหลายผู้ใช้พร้อมกัน ข้อมูลเก็บใน JSON และการแจ้งเตือนต้องเปิด Overview กับโปรแกรม Python ไว้ ระบบจึงเหมาะกับโครงงานที่ใช้งานในเครื่องตามข้อกำหนดนี้

ประโยชน์ที่ได้คือรู้ว่างานใดควรเริ่มวันนี้ เห็นเวลาที่ขาดก่อนถึงวันส่ง และติดตามความคืบหน้าได้ชัดเจนครับ ขอบคุณครับ”

## 7. คำถามที่ควรซ้อม

- **ทำไมใช้ JSON:** เป็นรูปแบบของ skeleton เหมาะกับข้อมูลเล็กในรายวิชา และยังไม่มีฐานข้อมูลหลายผู้ใช้
- **ทำไมปิดงานแล้วชั่วโมงจริงไม่เพิ่ม:** เป็นการประกาศว่างานเสร็จตามประมาณ ไม่ใช่การบันทึกเวลาทำจริง
- **ทำไมงานย่อยครบแต่เปอร์เซ็นต์อาจไม่ครบ:** งานย่อยวัดขั้นตอน ส่วนเปอร์เซ็นต์หลักวัดยอดชั่วโมง
- **กดฟอร์มเก่าหลังลบงานอื่นจะเกิดอะไร:** version และตำแหน่งไม่ตรง ระบบปฏิเสธและให้โหลดใหม่
- **ปิดเว็บแล้วยังเตือนหรือไม่:** ไม่มีการเตือนต่อจากเว็บ ใช้ไฟล์ปฏิทินที่นำเข้าแล้วและตรวจสิทธิ์ในแอปเอง
- **ได้ 100 คะแนนแล้วหรือไม่:** 60/60 เป็นส่วนอัตโนมัติ อีก 40 อาจารย์ประเมินทีมและการนำเสนอ
