## 2. เตรียมก่อนเริ่มนำเสนอ

1. เปิดโครงการและรันด้วย `run.bat` ตามคู่มืออาจารย์ ตรวจว่าที่อยู่ที่โปรแกรมแสดงเปิดได้ ปกติคือ `http://localhost:5000` หากใช้พอร์ตอื่นให้ใช้พอร์ตที่รันจริง ไม่ยึดลิงก์เก่าในบทสนทนา
2. สำรอง **`data.json` เป็นไฟล์ใหม่แยกจาก `data.sample.json`** ก่อนสาธิต ตั้งชื่อเช่น `data.before-demo-2026-09-29.json` แล้วเก็บไว้ในที่ปลอดภัย การสำรองนี้รักษาทั้งข้อมูลที่ใช้อยู่และข้อมูลตัวอย่างเดิม
3. หากจะรัน `check.bat` ต้องสำรองก่อน เพราะ `check_project.py` เรียก `storage.reset()` หลังตรวจ `handle({})` และอาจนำ `data.sample.json` มาทับ `data.json` หลังตรวจเสร็จให้คืนไฟล์สำรองมายัง `data.json` เมื่อต้องการข้อมูลเดิม **ไม่จำเป็นต้องทับไฟล์ตัวอย่างเพื่อสำรองข้อมูลจริง**
4. เปิดหน้าแรก `/`, `/page1`, `/page2`, `/page3` และ `/team` ตรวจชื่อกลุ่มกับสมาชิก
5. เตรียมงานสาธิตที่ชื่อสังเกตง่าย เช่น “งานสาธิตก่อนนำเสนอ” วิชา “การเขียนโปรแกรม” วันส่งเป็นวันพรุ่งนี้ ใช้เวลา 4 ชั่วโมง เริ่มต้นทำแล้ว 0 ชั่วโมง ตัวอย่างนี้จะเพิ่มจากหน้า 2 ขณะสาธิตและลบเมื่อจบได้
6. ทดลองสิทธิ์แจ้งเตือนก่อนวันนำเสนอ ถ้าเตือนไปแล้วในวันนั้น โค้ดจะพยายามป้องกันการเตือนซ้ำรายวัน จึงไม่ควรรับปากว่าจะมีหน้าต่างเตือนปรากฏทุกครั้งที่กด
7. เก็บภาพหน้าจอของทั้งสามหน้าไว้เป็นตัวสำรอง และเตรียมไฟล์ `FLOWCHARTS.md` กับเอกสารอธิบายโค้ดไว้เปิดกรณีเว็บไซต์มีปัญหา
8. ไม่ต้องนำเข้าไฟล์ปฏิทินจริงระหว่างสาธิตหากเวลาไม่พอ แสดงไฟล์ `.ics` ที่ดาวน์โหลดและอธิบายขั้นตอนนำเข้าได้ โดยกล่าวให้ชัดว่าการดาวน์โหลดเพียงอย่างเดียวยังไม่สร้างการเตือนในปฏิทิน

### ข้อมูลปัจจุบันและการอ้างตัวเลขระหว่างพูด

ไฟล์ `data.json` ที่ตรวจอ่านมี **7 งาน** ไม่มีงานที่ `done_hours` เท่ากับ `estimated_hours` และมีชั่วโมงคงเหลือรวม **29 ชั่วโมง** หากวันที่ฝั่ง Python เป็น 2026-09-29 โดยไม่มีการแก้ข้อมูล จะมีงานเกินกำหนด 3 งาน งานส่งภายใน 3 วันรวมวันนี้ 1 งาน ตัวเลขนี้เป็นการคำนวณจากข้อมูล ณ วันที่ระบุ ไม่ใช่ค่าถาวรของระบบ

ระหว่างนำเสนอให้ชี้ตัวเลขบนหน้าจอจริงและใช้คำว่า “จากข้อมูลที่กำลังแสดง” หากวันนำเสนอหรือข้อมูลเปลี่ยน ไม่ต้องอ่านค่าคงที่ข้างต้น

## 7. บทพูดสำรองเมื่อสาธิตติดขัด

### เว็บไซต์เปิดไม่ได้

“ขณะนี้หน้าเว็บในเครื่องสาธิตยังเปิดไม่ได้ครับ/ค่ะ ขออธิบายจากภาพหน้าจอและผังการทำงานที่เตรียมไว้ก่อน โดยข้อมูลไหลจากฟอร์มเข้าสู่ Python ตรวจสอบแล้วบันทึก JSON จากนั้นแต่ละหน้าจึงอ่านกลับมาคำนวณและแสดงผล เราจะระบุให้ชัดว่าขณะนี้ยังไม่ได้สาธิตการทำงานสดในเครื่องนี้ครับ/ค่ะ”

ผู้ดูแลตรวจว่าโปรแกรมยังรันอยู่ ที่อยู่และพอร์ตตรงกับข้อความในหน้าต่างโปรแกรม และไม่มีโปรแกรมอื่นใช้พอร์ตนั้น หลีกเลี่ยงแก้โค้ดหลายจุดต่อหน้าผู้ชมโดยไม่ทราบสาเหตุ

### เบราว์เซอร์ไม่อนุญาตแจ้งเตือน

“เบราว์เซอร์ของเครื่องนี้ปิดกั้นสิทธิ์การแจ้งเตือน จึงยังแสดงหน้าต่างเตือนไม่ได้ครับ/ค่ะ ตัวเว็บจะแสดงข้อความสถานะ และผู้ใช้ต้องเปลี่ยนสิทธิ์ของเว็บไซต์จากการตั้งค่า หากต้องการเตือนหลังปิดเว็บ เรามีทางเลือกส่งออกไฟล์ปฏิทินแล้วนำเข้าเอง ซึ่งขึ้นกับการตั้งค่าของแอปปฏิทินด้วยครับ/ค่ะ”

### อนุญาตแล้วแต่ไม่มีหน้าต่างเตือน

“การเตือนอาจถูกบันทึกว่าแสดงแล้วในวันนี้ หรือไม่มีงานที่เข้าเกณฑ์ครับ/ค่ะ โค้ดจึงไม่สร้างการเตือนใหม่ทุกครั้งที่กดปุ่ม เราขอแสดงเงื่อนไขจากผังงานประกอบ และใช้ข้อความสถานะบนหน้าเป็นหลักฐานว่าขอสิทธิ์สำเร็จ โดยยังไม่กล่าวว่าเครื่องนี้แสดงหน้าต่างเตือนแล้วครับ/ค่ะ”

### ผลคำนวณต่างจากสคริปต์

“ผลนี้ใช้วันที่ของเครื่องและข้อมูลล่าสุด จึงเปลี่ยนได้ตามวันนำเสนอครับ/ค่ะ ขออธิบายจากตัวเลขที่กำลังแสดง โดยคงสูตรเดิม คือชั่วโมงงานสะสมเทียบกับจำนวนวันรวมวันนี้คูณเวลาที่ทำได้ต่อวันครับ/ค่ะ”

### อาจารย์ถามว่าใครเขียนโค้ดด้วยตนเอง

“ทีมใช้ผู้ช่วย AI ช่วยจัดทำและอธิบายโค้ดตามเงื่อนไขของรายวิชาครับ/ค่ะ ส่วนการแบ่งหน้าที่เป็นไปตามหน้าทีม สมาชิกแต่ละคนต้องตรวจความเข้าใจและอธิบายส่วนที่รับผิดชอบได้ สำหรับหลักฐานการแก้ไขรายคนขออ้างอิงประวัติ Git ที่มีจริงครับ/ค่ะ”

## 8. รายการซ้อมตอบของแต่ละคน

- **วายุ:** อธิบายคุณสมบัติห้าตัว, `__init__`, `self`, `max`, `date.fromisoformat`, ความต่างระหว่างข้อมูลในไฟล์กับวัตถุในหน่วยความจำ และเหตุผลที่ใช้คลาสร่วมกัน
- **ลักขณา:** ไล่เงื่อนไขสถานะตามลำดับ, อธิบายเหตุใดงานเสร็จแล้วไม่เตือน, การรวมยอด, การวนเลือกเรียงงาน, เงื่อนไขใกล้ส่ง 0–3 วัน, ขอบเขตการเตือนและการส่งออกปฏิทิน
- **ไกรวิชญ์:** แยก `build` กับ `handle`, คำสั่ง `add/update/delete`, `read_hours`, `check`, เงื่อนไขก่อนบันทึก, ตำแหน่งรายการที่เริ่มศูนย์, Jinja loop และ hidden input
- **ธีรเดช:** อธิบายการกรองงาน, การเรียง, ตัวแปรชั่วโมงสะสม, การนับวันนี้, งานเกินกำหนด, การปัดเศษ, ขอบเขตของตัวตรวจอาจารย์ และผลข้างเคียงของ `storage.reset()`

ก่อนส่งจริงให้แต่ละคนอ่านโค้ดของส่วนตนพร้อมเอกสารอธิบายรายบรรทัด แล้วลองอธิบายโดยไม่อ่านบทพูดหนึ่งรอบ การท่องชื่อฟังก์ชันอย่างเดียวไม่เพียงพอสำหรับอธิบายเหตุผลของเงื่อนไข
