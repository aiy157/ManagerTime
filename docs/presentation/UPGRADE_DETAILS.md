## 1. เป้าหมายและวิธีใช้งาน

ระบบช่วยตอบสามคำถาม: วันนี้ควรเริ่มงานใด มีเวลาทำทันหรือไม่ และทำไปแล้วเท่าไร เปรียบเหมือนจัดกระเป๋าเดินทาง: งานคือสิ่งของ ชั่วโมงคือขนาด และเวลาว่างคือความจุ หากเกินความจุต้องจัดลำดับหรือปรับแผนก่อน

1. เปิด **จัดการงาน** เพิ่มชื่อ วิชา วันส่ง ชั่วโมงทั้งหมด และชั่วโมงที่ทำแล้ว
2. เลือกความสำคัญและผู้รับผิดชอบ แบ่งเป็นงานย่อยถ้างานใหญ่
3. เปิด **แผนก่อนวันส่ง** บันทึกเวลาว่างจริงต่อวัน
4. เปิด **ภาพรวมงาน** ดูงานที่ควรเริ่มวันนี้ เหตุผล และชั่วโมงที่แบ่งให้
5. กด **เริ่มงานนี้** เพื่อเปลี่ยนเป็นกำลังทำ
6. ใช้ **บันทึกเวลา / งานย่อย** หลังทำงานแต่ละครั้ง กรอกชั่วโมงของครั้งนั้น
7. กด **ทำเครื่องหมายว่าเสร็จแล้ว** ได้ทันทีโดยไม่ต้องกรอกชั่วโมงครบ
8. เปิด **ทีม** ดูการกระจายงานและรายการที่ยังไม่มอบหมาย

รัน `run.bat` แล้วเปิดที่อยู่ที่โปรแกรมแจ้ง ปกติคือ `http://localhost:5000` ต้องเปิดโปรแกรมฝั่ง Python ไว้ขณะใช้เว็บไซต์

## 3. เหตุผลที่คงเทคโนโลยีเดิม

ใช้ Python + Flask + HTML/Jinja + CSS ของอาจารย์ เพราะงานนี้ต้องรักษา skeleton และอธิบายพื้นฐาน Python ได้ เพิ่มความสามารถผ่าน `build()` และ `handle(form)` ตามสัญญาเดิม ใช้ loop และ if ที่อ่านตามลำดับได้ ไม่มี package ใหม่

- `models.py` รวมสูตร สถานะ ลำดับงาน และการเปลี่ยนสถานะให้ทุกหน้าใช้กติกาเดียวกัน
- `pages/*.py` เตรียมข้อมูลและรับฟอร์ม
- `templates/*.html` แสดงผลผ่านแม่แบบเดิม
- `storage.load()/save()` อ่านและเขียนข้อมูลงาน
- JavaScript ใช้ช่วยตรวจฟอร์ม เปิดการ์ดจากทางลัด แจ้งเตือน และดาวน์โหลดปฏิทิน
- CSS เพิ่มเฉพาะส่วนท้ายไฟล์ โดยรักษาส่วนเดิม

การออกแบบใช้สีแดงเลือดหมู `#7a1f2b` สีทอง `#e6b422` พื้นหลัง `#f7f5f2` และตัวอักษรเข้ม `#1f2933` ตามธีมคณะ ฟอนต์ใช้ชุดที่มีในเครื่อง เช่น Segoe UI, Sarabun, Noto Sans Thai ไม่จำเป็นต้องโหลดจากอินเทอร์เน็ต ไม่ใช้สีเป็นสัญญาณสถานะเพียงอย่างเดียว

```json
{
  "title": "โครงงานเขียนโปรแกรม",
  "course": "การเขียนโปรแกรม",
  "due_date": "2026-10-04",

  "priority": "high",
  "details": {
    "owner": "69130840182",

      {"title": "ออกแบบระบบ", "done": false}

      {"date": "2026-09-30", "hours": 2, "kind": "work", "note": "ออกแบบหน้าจอ"}
    ],
    "created_on": "2026-09-30",
    "progress_on": "2026-09-30"

```

ตัวอย่างนี้ใช้เพื่ออธิบาย schema ไม่ได้เพิ่มประวัติหรือมอบหมายงานในข้อมูลจริง

| Field | ความหมาย |
|---|---|
| title | ชื่องาน 1–80 ตัวอักษรหลังตัดช่องว่างริมข้อความ |
| course | วิชา 1–40 ตัวอักษร |
| due_date | วันส่งรูปแบบ YYYY-MM-DD ที่เป็นวันที่จริง |
| estimated_hours | ชั่วโมงรวมที่คาดว่าจะใช้ 0.1–200 |
| done_hours | ยอดความคืบหน้าตั้งแต่ 0 ถึงชั่วโมงรวม |
| priority | high / normal / low |
| details | ผู้รับผิดชอบ สถานะเริ่ม งานย่อย ประวัติ และวันที่อัปเดต |

ข้อมูลเดิม 5 field ยังอ่านได้ โดยให้ความสำคัญปกติและรายละเอียดเริ่มต้น งานตัวอย่าง 7 รายการรักษาชื่อ วันส่ง และยอดชั่วโมงเดิม ไม่สร้างวันที่ทำงานย้อนหลังและไม่กำหนดผู้รับผิดชอบแทนผู้ใช้

`planner_settings.json` เก็บ `{"daily_hours": 2}` แยกจากรายการงาน ใช้ค่าเดียวกันระหว่าง Overview และ Plan หากไฟล์หายหรือค่าผิดให้ใช้ 2 ชั่วโมงต่อวัน ค่าใหม่ต้องอยู่ช่วง 0.1–12 ชั่วโมง

## 5. สถานะและลำดับงาน

**สถานะการทำงาน**

- ○ ยังไม่เริ่ม: ยังไม่กดเริ่ม และชั่วโมงที่ทำแล้วเป็นศูนย์
- ▶ กำลังทำ: กดเริ่ม หรือมีชั่วโมงที่ทำแล้ว
- ✓ เสร็จแล้ว: ชั่วโมงคงเหลือเป็นศูนย์

**สถานะกำหนดส่ง** เป็นป้ายอีกชุดหนึ่ง: ใกล้ถึงกำหนดเมื่อส่งวันนี้ถึงอีก 3 วัน; เกินกำหนดเมื่อวันส่งก่อนวันนี้; งานเสร็จไม่แสดงคำเตือนวันส่ง

การเรียงเทียบเกณฑ์ทีละข้อ: งานเกินกำหนดก่อน → วันส่งใกล้ก่อน → ชั่วโมงคงเหลือมากก่อน → งานเสี่ยงก่อน → ความสำคัญสูงก่อน → ตำแหน่งเดิมในข้อมูล เมื่อต่างกันในเกณฑ์ก่อนหน้าจะไม่ใช้เกณฑ์ถัดไปทับลำดับ ใช้ selection loop เพื่อให้เหมาะกับบทเรียน

## 6. สูตรการวางแผนและเวลาวันนี้

- ชั่วโมงคงเหลือ = `max(0, estimated_hours - done_hours)`
- ความคืบหน้า = ชั่วโมงที่ทำแล้ว ÷ ชั่วโมงทั้งหมด × 100 ตัดเศษเป็นจำนวนเต็ม จำกัด 0–100
- วันคงเหลือ = วันส่ง − วันนี้
- งานสะสมถึงวันส่งหนึ่ง = รวมชั่วโมงคงเหลือของทุกงานที่ส่งก่อนหรือเท่ากับวันนั้น รวมงานเกินกำหนด
- ชั่วโมงทำจริงวันนี้ = รวม `history.kind == "work"` ที่วันที่ตรงกับวันนี้ รวมจากงานที่เสร็จแล้วด้วย
- เวลาที่ใช้ในการคำนวณความจุ = น้อยกว่าระหว่างชั่วโมงทำจริงวันนี้กับเวลาว่างรายวัน
- จำนวนวันทำได้ = วันคงเหลือ + 1 เพราะรวมวันนี้
- ความจุที่ยังใช้ได้ = จำนวนวัน × เวลาว่างรายวัน − เวลาที่ใช้วันนี้ในความจุ
- ชั่วโมงเฉลี่ยที่ต้องทำ = (งานสะสมที่เหลือ + เวลาที่ใช้วันนี้ในความจุ) ÷ จำนวนวัน
- ขาดรวม = `max(0, งานสะสม - ความจุที่ยังใช้ได้)`
- ขาดต่อวัน = `max(0, ชั่วโมงเฉลี่ยที่ต้องทำ - เวลาว่างรายวัน)`

งานส่งวันเดียวกันใช้ภาระสะสมเดียวกัน จึงไม่มีรายการหนึ่งขึ้น “ตามแผน” ทั้งที่ภาระรวมวันนั้นเกินเวลา

ค่าชั่วโมงต่อวันและส่วนขาดปัดขึ้นเป็นทศนิยม 1 ตำแหน่ง เช่น ขาดจริง 0.01 ชั่วโมง แสดงขาด 0.1 ชั่วโมง และยังเป็นเวลาไม่พอ ตัดสินความเสี่ยงก่อนปัดตัวเลข

**ตัวอย่าง:** เหลืองาน 18 ชั่วโมง ส่งพรุ่งนี้ ยังไม่บันทึกเวลาวันนี้ ว่างวันละ 4 ชั่วโมง → มี 2 วัน ความจุ 8 ชั่วโมง ต้องทำเฉลี่ย 9 ชั่วโมง/วัน ขาด 5 ชั่วโมง/วัน หรือรวม 10 ชั่วโมง

**หลังทำงานวันนี้:** ว่าง 2 ชั่วโมง ทำจริงแล้ว 1 ชั่วโมง และยังเหลืองานส่งวันนี้ 2 ชั่วโมง → เหลือความจุวันนี้ 1 ชั่วโมง ขาดรวม 1 ชั่วโมง คำแนะนำจะจัดเวลาเพิ่มไม่เกิน 1 ชั่วโมง

งานเกินกำหนดใช้สถานะ “เกินกำหนด” ไม่คำนวณหารด้วยจำนวนวันติดลบ ควรติดต่อผู้สอนและจัดการก่อน ภาระงานนี้ยังถูกนับเมื่อวางแผนวันส่งในอนาคต

หน้า Plan แสดงค่าเฉลี่ยที่สูงที่สุดในช่วงกำหนดส่งที่ยังไม่ผ่าน ไม่ใช่การบวกค่าเฉลี่ยของทุกงานซ้ำกัน ระบบสมมติว่าทุกวันมีเวลาว่างเท่ากัน และยังไม่แยกวันหยุด ตารางเรียน หรือเวลาส่งระดับนาที

## 7. คำแนะนำวันนี้

แบ่งเวลาว่างที่เหลือวันนี้ให้แต่ละงานตามลำดับ โดยใช้ `min(ชั่วโมงงานที่เหลือ, งบเวลาวันนี้ที่เหลือ)` หยุดจัดสรรเมื่อหมดเวลา รวมเวลาแนะนำไม่เกินงบจริง

เหตุผลอัตโนมัติ:

- เกินกำหนด: ติดต่อผู้สอนและจัดการก่อน
- ส่งภายใน 3 วัน: ใกล้ถึงกำหนด ควรเริ่มก่อน
- เหลืออย่างน้อย 6 ชั่วโมง: ใช้เวลามาก ควรแบ่งงานย่อย
- ภาระสะสมมากกว่าเวลาว่าง: เสี่ยงไม่ทัน
- ความสำคัญ high: ตั้งความสำคัญไว้สูง
- กรณีทั่วไป: เป็นลำดับวันส่งใกล้สุดที่เหลือ

หากบันทึกเวลาครบงบวันนี้แต่ยังมีงานค้าง ระบบแจ้งว่าครบเวลาว่างแล้วและให้ดูแผนวันถัดไป ไม่แสดงว่างานทั้งหมดเสร็จ

## 8. การบันทึกและการจบงาน

| วิธี | ผลต่อความคืบหน้า | ประเภทประวัติ | รวมชั่วโมงทำจริงหรือไม่ |
|---|---|---|---|
| บันทึกเวลาครั้งนี้ | เพิ่มชั่วโมงครั้งนี้เข้า done_hours | work | รวม |
| แก้ยอดชั่วโมงที่ทำแล้ว | เปลี่ยนยอดสะสม | adjustment | ไม่รวม |
| ทำเครื่องหมายเสร็จ | ตั้ง done_hours เท่า estimated_hours และปิดงานย่อย | complete | ไม่รวม |
| เปิดกลับมาทำต่อ | คืนยอด/สถานะงานย่อยก่อนกดปิด | reopen | ไม่รวม |

การกดปิดงานเป็นการประกาศว่างานเสร็จ จึงไม่ควรอ้างว่าชั่วโมงประมาณที่เหลือคือชั่วโมงทำงานจริง วันที่ของประวัติ work เป็นวันที่ผู้ใช้เลือก และห้ามเลือกอนาคต

ปุ่มเปิดกลับใช้เฉพาะงานที่เคยกดปิดผ่านปุ่ม หากบันทึกเวลาจริงจนครบ ให้แก้ยอดหรือเวลาประมาณผ่านฟอร์มเมื่อจำเป็น การแก้ยอดลงต่ำกว่าเวลาประมาณจะล้างข้อมูลยกเลิกการปิดเก่า

งานย่อยและชั่วโมงติดตามคนละมิติ ติ๊กขั้นตอนแล้วชั่วโมงไม่เพิ่มเอง; บันทึกชั่วโมงจนครบไม่ได้บังคับว่าทุกขั้นตอนถูกติ๊ก ตัวเลขงานย่อยจึงยังสะท้อนค่าจริง

## 9. การตรวจฟอร์มและป้องกันการแก้ผิดรายการ

ตรวจทั้งเบราว์เซอร์และ Python หากปิด JavaScript หรือส่งฟอร์มเอง Python ยังคงปฏิเสธข้อมูลผิด

- ชื่อ/วิชาห้ามว่างหรือมีแต่ช่องว่าง
- วันส่งต้องจริงและรูปแบบมาตรฐาน ไม่รับ 30 กุมภาพันธ์หรือ YYYYMMDD
- ชั่วโมงห้ามติดลบ ไม่รับ NaN/Infinity และยอดที่ทำห้ามมากกว่าเวลาทั้งหมด
- ผู้รับผิดชอบต้องเป็นสมาชิกใน team.json หรือไม่มอบหมาย
- วันส่งที่ผ่านแล้วเพิ่มได้เมื่อยืนยันว่าเป็นงานค้าง; งานเดิมที่วันส่งผ่านแล้วแก้ข้อมูลอื่นได้
- บันทึกเวลาครั้งนี้ 0.1 ชั่วโมงขึ้นไป และไม่เกินเวลาคงเหลือ
- งานย่อยไม่เกิน 30 รายการ ชื่อไม่เกิน 100 ตัวอักษร; หมายเหตุการทำงานไม่เกิน 120 ตัวอักษร
- ฟอร์มเดิมมีตำแหน่ง row และ SHA-256 ของเนื้อหา หากรายการเลื่อนจากการลบ หรือรายการถูกแก้ก่อนหน้า จะปฏิเสธและขอโหลดใหม่

ค่า SHA-256 เป็นตัวตรวจว่าฟอร์มเก่าใช้กับข้อมูลเวอร์ชันเดิม ไม่ใช่รหัสลับ การยืนยันตัวตน หรือระบบล็อกขณะหลายคนบันทึกพร้อมกัน โครงนี้ใช้ JSON ทั้งไฟล์ จึงเหมาะกับการสาธิต/ใช้งานในเครื่องมากกว่าการเปิดเป็นระบบหลายผู้ใช้

Jinja escape ข้อความผู้ใช้ตามแม่แบบเดิม ไม่ใช้ `safe` กับชื่อที่กรอก

## 10. งานของทีม

รวมงานตาม `details.owner` ที่ตรงรหัสสมาชิก แสดงจำนวนงานทั้งหมด/ค้าง ชั่วโมงเหลือ ความคืบหน้าแบบถ่วงน้ำหนักตามชั่วโมง และรายชื่องาน

เกณฑ์ “ควรช่วยแบ่งงาน” คือมีงานเสี่ยงตามวันส่ง หรือชั่วโมงค้างมากกว่าเวลาว่างรายวัน × 7 ค่านี้ใช้เกณฑ์รายวันเดียวสำหรับสมาชิกทุกคน เป็นสัญญาณช่วยพูดคุย ไม่ใช่คะแนนการทำงานของสมาชิก

เปอร์เซ็นต์ทีมใช้ยอดความคืบหน้า `done_hours` รวมผลการกดปิดงาน ไม่ใช่สัดส่วนชั่วโมงทำจริงจากประวัติ หากไม่มีงานจะแสดง 0% และไม่มีงานค้างที่มอบหมาย

สมาชิกที่ยังไม่ได้รับงานจะไม่ถูกมอบหมายอัตโนมัติ ปุ่มมอบหมายพาไปการ์ดงานใน Manage เพื่อเลือกคนและบันทึก

## 11. การแจ้งเตือน

หน้า Overview ส่งข้อมูลเท่าที่ต้องใช้ผ่าน JSON และ JavaScript ตรวจ pending ที่เข้าข้อใดข้อหนึ่ง:

1. ส่งวันนี้ถึงอีก 3 วัน หรือเกินกำหนด
2. แผนเสี่ยงไม่ทัน
3. มีเวลาแนะนำให้ทำวันนี้
4. ยังไม่มีวันที่อัปเดต หรือไม่ได้อัปเดตตั้งแต่ 2 วันขึ้นไป

ผู้ใช้กดเปิดเพื่อขอสิทธิ์ ระบบตรวจหน้าเดิมทุก 60 วินาที และเมื่อกลับมาเปิดแท็บ ใช้ fetch แบบไม่เก็บ cache กำหนดเวลารอ 10 วินาที หากดึงข้อมูลไม่ได้ให้เก็บข้อมูลล่าสุดที่มี

เมื่อข้อมูลเปลี่ยน แสดงลิงก์โหลดภาพรวมใหม่ รายการที่วาดอยู่ยังไม่ถูกแทนที่อัตโนมัติ การตัดสินใจแจ้งเตือนใช้ข้อมูลที่เพิ่งดึงได้

จำชุดงานและเหตุผลที่เตือนไว้ตามวันในตัวแปรและ localStorage จึงไม่เตือนซ้ำทุกนาทีเมื่อข้อมูลเดิม ชั่วโมงที่แก้เล็กน้อยอย่างเดียวไม่สร้างการเตือนใหม่ ไม่มีการรับประกันการป้องกันซ้ำระหว่างหลายแท็บหรือหลายเครื่อง

**ข้อจำกัด:** ต้องเปิดหน้า Overview และโปรแกรม Python ไว้ สิทธิ์เบราว์เซอร์/อุปกรณ์อาจปิดกั้นหรือหน่วงการเตือน ไม่มี service worker หรือ push เมื่อปิดหน้า กรณีนี้ใช้ไฟล์ปฏิทิน .ics ซึ่งเป็นกิจกรรมทั้งวัน ขอเตือนก่อน 1 วัน ผู้ใช้ต้องนำเข้าและตรวจการเตือนในแอปปฏิทินเอง ไฟล์ไม่ซิงก์เมื่อแก้งาน
