## 1. สิ่งที่ต้องอธิบายให้ได้

ผู้ทดสอบต้องเทียบผลกับคำตอบที่คำนวณไว้ล่วงหน้า ไม่พิจารณาเพียงว่าหน้าเปิดได้ ตรวจสามส่วน: ข้อมูลบันทึกถูกต้อง สถานะเปลี่ยนถูกต้อง และเวลาที่แนะนำไม่เกินเวลาว่างจริง

- **Overview:** งานค้าง/เสร็จ เหตุผล งานวันนี้ และการหักเวลาที่ใช้แล้ว
- **Manage:** เพิ่ม/แก้/ลบ ชั่วโมงจริง งานย่อย ผู้รับผิดชอบ และข้อมูลผิด
- **Plan:** ภาระสะสม ความจุ ชั่วโมงที่ต้องทำ และเวลาที่ขาด
- **Team:** จำนวนงาน ความคืบหน้า ภาระมาก และงานที่ยังไม่มอบหมาย
- **มือถือ/แจ้งเตือน:** เมนู ปุ่ม ตาราง และข้อจำกัดการเตือน

## 3. สูตรหน้า Plan ที่ต้องรู้

1. ชั่วโมงคงเหลือ = ชั่วโมงทั้งหมด − ชั่วโมงที่ทำแล้ว ไม่ต่ำกว่าศูนย์
2. งานสะสม = รวมงานค้างทุกชิ้นที่วันส่งก่อนหรือเท่ากับวันส่งที่กำลังตรวจ
3. จำนวนวัน = วันคงเหลือ + 1 รวมวันนี้
4. ชั่วโมงจริงวันนี้ = รวมประวัติประเภท work ของวันนี้เท่านั้น
5. ความจุคงเหลือ = จำนวนวัน × เวลาว่างต่อวัน − เวลาที่ใช้วันนี้ โดยหักไม่เกินเวลาว่างวันนี้
6. ต้องทำเฉลี่ย = (งานสะสมที่เหลือ + เวลาที่หักวันนี้) ÷ จำนวนวัน
7. ขาดรวม = งานสะสม − ความจุ หากติดลบใช้ศูนย์
8. ขาดเฉลี่ยต่อวัน = ต้องทำเฉลี่ย − เวลาว่างต่อวัน หากติดลบใช้ศูนย์
9. ตัดสินความเสี่ยงจากส่วนขาดจริงก่อนปัดขึ้น 1 ตำแหน่ง
10. งานเกินกำหนดไม่หารด้วยจำนวนวันติดลบ ให้ป้ายเกินกำหนดและรวมภาระไปงานอนาคต

## 5. รันตรวจโดยรักษาข้อมูลจริง

`check.bat` เรียกตัวตรวจอาจารย์และ pytest ตัวตรวจคืน `data.json` จาก `data.sample.json` จึงต้องสำรองงานจริงเป็นไฟล์ใหม่แยกก่อน และคืนหลังตรวจ หากต้องการเก็บตัวอย่างเดิม อย่าทับ sample เพื่อสำรอง

```powershell
# ตรวจ pytest อย่างเดียว: กรณีที่เพิ่มใช้ข้อมูลชั่วคราว
.venv\Scripts\python.exe -m pytest -q

# JavaScript: ต้องมี Node.js อยู่แล้ว ไม่ต้องติดตั้ง package
node --test docs/qa/test_reminders.cjs

# เว็บสาธิตข้อมูลชั่วคราวสำหรับทดลองเพิ่ม/จบ/ลบงาน
.venv\Scripts\python.exe docs/qa/serve_fixture.py
# เปิด http://127.0.0.1:5002/page1
```

เว็บทดสอบพอร์ต 5002 แยก data และ settings ด้วย TemporaryDirectory จากงานจริง หยุดด้วย Ctrl+C เมื่อจบการตรวจ

ไฟล์ห้ามแก้: `app.py`, `storage.py`, `check_project.py`, `test_pages.py`, `base.html` และ `_not_built.html` ไม่แก้ `check.bat` เพื่อทำให้คะแนนผ่าน

## 6. วิธีรายงานข้อผิดพลาด

ระบุ: รหัสกรณีทดสอบ → หน้า/ขนาดจอ/เบราว์เซอร์ → ข้อมูลก่อนทำ → ขั้นตอน → ผลที่ควรได้ → ผลจริง → ภาพหน้าจอ → เวลาตรวจ ห้ามเขียนเพียง “ใช้งานไม่ได้”

ความเสี่ยงที่ต้องอธิบาย: JSON ไม่ใช่ฐานข้อมูลหลายผู้ใช้; hash เวอร์ชันฟอร์มไม่ใช่ล็อกพร้อมกัน; ปิดหน้า Overview แล้วไม่มีการเตือนต่อ; ไฟล์ปฏิทินไม่ซิงก์หลังแก้งาน; ยังไม่มี login และยังไม่ใช่ PWA ที่ติดตั้งใช้ได้โดยไม่เปิด Python
