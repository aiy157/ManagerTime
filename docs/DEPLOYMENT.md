# การบันทึกข้อมูลบน localhost และโฮสต์ออนไลน์

เดดไลน์ไม่ชนกัน · CodeMind กลุ่ม 6 · 1 ตุลาคม 2569

## ข้อผิดพลาดที่แก้ไข

ภาพข้อผิดพลาดแสดง `OSError: [Errno 30] Read-only file system: '/var/task/data.json'` ระหว่างกดปุ่มในหน้า 2 ระบบอ่านรายการได้ แต่เขียนกลับไปยังพื้นที่ไฟล์โครงการไม่ได้

Vercel Functions มีพื้นที่ไฟล์ที่อ่านอย่างเดียว และมี `/tmp` สำหรับเขียนข้อมูลชั่วคราว ตาม [เอกสาร Vercel](https://vercel.com/docs/functions/runtimes#file-system-support) การใช้พื้นที่ชั่วคราวจึงช่วยให้สาธิตการบันทึกได้ แต่ไม่ได้ทำให้ข้อมูลกลายเป็นข้อมูลถาวรหรือใช้ร่วมกันทุก instance

## วิธีทำงานหลังแก้ไข

`models.configure_storage()` ทำงานหนึ่งครั้งเมื่อ Python นำเข้า `models` ก่อนเรียกการทำงานของหน้าเว็บ:

1. อ่านตัวแปรสภาพแวดล้อม `DEADLINE_DATA_DIR` หากผู้ดูแลกำหนดไว้
2. หากไม่ได้กำหนด ใช้โฟลเดอร์โครงการ และลองเปิดไฟล์ว่างชั่วคราวที่ลบตัวเองเมื่อปิด เพื่อทดสอบสิทธิ์เขียนโดยไม่แก้เนื้อหา `data.json`
3. หากพื้นที่เดิมเขียนไม่ได้ด้วย `EROFS`, `EACCES` หรือ `EPERM` ให้เลือกโฟลเดอร์ `deadline-compass-<รหัส>` ใต้พื้นที่ชั่วคราวของระบบ Linux โดยทั่วไปคือ `/tmp`
4. คัดลอก `data.json` และ `planner_settings.json` จากโครงการเฉพาะไฟล์ที่ยังไม่มีปลายทาง การสร้างด้วยโหมด `x` ไม่ทับไฟล์ปลายทางที่มีอยู่แล้ว
5. กำหนด `storage.DATA_FILE` และ `models.SETTINGS_FILE` ให้ชี้ไปยังปลายทางเดียวกัน จากนั้นทุกหน้าใช้ `storage.load()` / `storage.save()` ตามเดิม
6. หากเลือกพื้นที่ชั่วคราวอัตโนมัติ ให้ Overview, Manage, Plan และ Team แสดงข้อความว่าข้อมูลอาจหายหรือไม่ต่อเนื่องเมื่อระบบเริ่มใหม่ หน้า Plan ยังคงแสดงข้อผิดพลาดการกรอกชั่วโมงควบคู่กันได้

ไฟล์ `storage.py` และ `app.py` คงเนื้อหาเดิม การกำหนดค่าตำแหน่งไฟล์ทำใน `models.py` ที่กลุ่มแก้ไขได้ `storage.SAMPLE_FILE` ยังชี้ไปชุดตัวอย่างเดิม เมื่อ reset จะคืนตัวอย่างลงใน `storage.DATA_FILE` ที่ใช้งานขณะนั้น

ข้อผิดพลาดอื่น เช่น พื้นที่เต็มหรืออุปกรณ์อ่านเขียนขัดข้อง ไม่ถูกซ่อนด้วยการย้ายไปพื้นที่ใหม่ หากกำหนด `DEADLINE_DATA_DIR` เองแต่ใช้งานไม่ได้ ระบบจะแสดงข้อผิดพลาดแทนการเปลี่ยนปลายทางเงียบ ๆ

## รูปแบบการใช้งาน

| สภาพแวดล้อม | ตำแหน่งข้อมูล | ข้อจำกัด |
|---|---|---|
| localhost ที่โฟลเดอร์โครงการเขียนได้ | `data.json` และ `planner_settings.json` ในโครงการ | เก็บข้ามการปิดและเปิดโปรแกรมได้ตราบใดที่ไฟล์ยังอยู่ |
| โฮสต์อ่านอย่างเดียว ไม่มีการกำหนดพื้นที่ถาวร | โฟลเดอร์ชั่วคราวของระบบ | ใช้สาธิตได้ ข้อมูลไม่รับประกันข้าม instance การเริ่มระบบใหม่ หรือการนำขึ้นระบบรอบใหม่ |
| เครื่องหรือโฮสต์ที่มีพื้นที่ถาวรเขียนได้ | โฟลเดอร์จาก `DEADLINE_DATA_DIR` | ผู้ดูแลต้องจัดหาพื้นที่ถาวรจริง ไม่ใช่เพียงตั้งชื่อตัวแปร |

ตัวอย่างสำหรับโฮสต์ที่มีดิสก์ถาวร mounted อยู่จริง:

```text
DEADLINE_DATA_DIR=/mnt/deadline-data
```

ตัวอย่างทดลองแยกข้อมูลบน Windows PowerShell:

```powershell
$env:DEADLINE_DATA_DIR = 'C:\dev\Code\runtime-data'
.venv\Scripts\python.exe app.py
```

ตั้งค่าเฉพาะเมื่อจำเป็น โฟลเดอร์ตัวอย่างนี้มีข้อมูลผู้ใช้ จึงไม่ควรนำเข้า Git เมื่อต้องการกลับไปใช้ข้อมูลโครงการใน session เดิม:

```powershell
Remove-Item Env:DEADLINE_DATA_DIR
```

**หากต้องการใช้งานออนไลน์หลายคนและเก็บถาวร:** ต้องต่อบริการจัดเก็บถาวรหรือฐานข้อมูลที่เหมาะกับโฮสต์เพิ่มเติม การย้าย JSON ไป `/tmp` ไม่แก้การใช้งานหลาย instance และการเขียนพร้อมกัน ไม่มีการเพิ่มฐานข้อมูล บัญชีผู้ใช้ หรือการซิงก์ในรอบนี้

## การทดสอบที่ทำแล้ว

ผลวันที่ 1 ตุลาคม 2569: `pytest` ผ่าน 55 กรณี ได้แก่ 42 กรณีเดิมและ 13 กรณีเพิ่มเติมสำหรับพื้นที่จัดเก็บ

ตัวตรวจอาจารย์ได้ 60/60 และไฟล์ห้ามแก้ 6 ไฟล์มี SHA-256 ตรงต้นฉบับ คืนเนื้อหาข้อมูลจริงหลังการตรวจแล้ว

- จำลอง `EROFS` โดยปฏิเสธการสร้างไฟล์ชั่วคราวในโฟลเดอร์ bundle
- ทดสอบการเริ่ม/ปิด/เปิดงานกลับ แก้ไข ลบ บันทึกเวลา เพิ่มและติ๊กงานย่อย ผ่าน POST หน้า 2
- ทดสอบเพิ่มงานและบันทึกชั่วโมงว่างใน Plan พร้อมอ่านค่าร่วมกันทุกหน้า
- ตรวจว่าเรียก initializer อีกครั้งไม่ทับงานและการตั้งค่าที่บันทึกไว้
- ตรวจว่า localhost ที่เขียนได้ยังใช้ไฟล์เดิม
- ตรวจปลายทางที่กำหนดเอง และการ reset โดยใช้ไฟล์ตัวอย่างชั่วคราว
- ตรวจว่า `ENOSPC` และ `EIO` ไม่ถูกปิดบัง

ทุกกรณีเพิ่มเติมใช้ข้อมูลชั่วคราวแยกจากข้อมูลจริง ส่วนนี้เป็นผลทดสอบในเครื่องที่จำลองเงื่อนไขโฮสต์ ยังไม่ใช่ผลตรวจ deployment Vercel จริง เพราะยังไม่มี URL และยังไม่ได้เผยแพร่โค้ดรอบนี้

## การนำโค้ดไปใช้งาน

1. localhost: เริ่มโปรแกรมใหม่ด้วย `run.bat` แล้วลองบันทึกที่ `/page2` และ `/page3`
2. Vercel: นำ source ที่แก้ไขขึ้น deployment ใหม่ แล้วลองการทำงานเดียวกัน ตรวจข้อความพื้นที่ชั่วคราวก่อนใช้เก็บงานจริง
3. หากต้องเก็บออนไลน์ถาวร ให้จัดหาพื้นที่ถาวรหรือบริการฐานข้อมูลก่อน ไม่ตั้ง `DEADLINE_DATA_DIR` เป็น `/var/task`
